# ETF 场内资金流分析 设计文档

> 状态：草案（待评审）
> 日期：2026-07-18
> 关联：复用 `get_capital_flow_context`（个股资金流 block）、`intelligence` 模块（service+endpoints+持久化）、`backfill` 持久化思路

## 1. 背景与问题

现有"主力资金"能力是**个股级**：`DataFetcherManager.get_capital_flow_context(stock_code)` 返回主力净流入 + 板块资金流榜，已作为 agent 工具 `get_capital_flow` 暴露（`src/agent/tools/data_tools.py`）。但该链路在 `data_provider/base.py` 的 `get_capital_flow_context` 中显式对 ETF 返回 `not_supported`（`_is_etf_code(stock_code)` 分支）。

ETF 维度目前**缺**：
- ETF 净流入排行
- ETF 份额变动（净申购 / 赎回 = 机构真实加减仓）
- ETF 折溢价（IOPV 偏离）
- 跨 ETF 的板块轮动 / 全市场资金流向聚合视图

**目标**：通过 A 股场内 ETF 每日变化，辅助判断主力资金去向，服务三类分析问题：
- **A 板块 / 主题轮动**：行业 / 主题 ETF 的资金进出来看轮动
- **B 宽基指数级动向（含国家队）**：300 / A500 / 500 / 1000 / 科创50 / 创业板等宽基 ETF 的份额净申购 + 折溢价
- **C 全市场 ETF 资金流总览**："今天钱去了哪 / 撤了哪"的全景

## 2. 目标与非目标

### 目标
- 每日产出 ETF 维度资金流情报（A/B/C 三视角），落库
- 注入每日大盘复盘报告"资金方向"段（交付面 ①）
- `dsa-web` 新增 ETF 资金流看板（交付面 ②）
- 复用现有多源 + fail-open 护栏，**不新造数据源**

### 非目标（本期不做）
- 全量历史时序自建 + 回填（provider 已给多日历史，自建性价比低；留待长期统计需求）
- 纯实时 / intraday（本期日频，收盘后批量）
- 港股 / 美股 ETF（本期仅 A 股场内 ETF）
- 自动交易 / 择时信号（仅情报呈现 + 报告辅助，不直接产出交易决策）

## 3. 关键决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 用途 | A 板块轮动 + B 宽基动向 + C 全市场总览 | 共用同一份数据底座，三视角切片 |
| 交付面 | ① 每日报告（注入现有"资金方向"段）+ ② Web 看板 | 报告出结论摘要、Web 出完整看板 |
| ETF 范围 | 混合：C 用批量接口全市场排行；A/B 每板块/每指数**按规模取前 10** | 全市场广度 + 聚焦可控；前 10 直接从批量数据算，不额外多打请求 |
| 排序指标 | **总规模**（+ 成交额流动性下限，剔迷你 / 低活跃） | 规模稳定代表性强；净流入是"要测的信号"，不作入选标准 |
| 聚合 | **绝对量求和、比率规模加权平均**（禁止简单平均） | 避免迷你 ETF 极端值拉偏 |
| 持久化 | 方案 A 轻量持久化：每日一份 JSON 快照，Web 读库 | Web 快且稳、可审计；趋势借 provider 历史；存储最小 |

### 聚合规则（关键，禁止简单平均）
设某桶（板块 / 指数）前 10 成员为 `{(规模 sᵢ, 指标 mᵢ)}`，总规模 `S = Σsᵢ`：
- **绝对量类**（净流入额、份额净变动额）→ **求和**：`F_桶 = Σfᵢ`。这才是"桶总共进了多少钱"，用于桶间排序。
- **比率 / 强度类**（涨幅%、净流入率%、折溢价%、份额变动率%）→ **规模加权平均**：`M_桶 = Σ(sᵢ × mᵢ) / S`。
- **连续净流入天数**：看"桶净流入（求和）"的连续正负符号。

## 4. 架构与落点

仿 `intelligence` 模块（service + endpoints + schemas + 持久化 items）与 `get_capital_flow_context` 的 block 模式（带 `status / source_chain / warnings`，fail-open）。边界清晰、各自可单测。

| 层 | 文件 | 职责 |
|---|---|---|
| 数据采集 | `data_provider/akshare_fetcher.py`、`data_provider/efinance_fetcher.py` | 加批量 ETF spot / 资金流 / 份额 / 折溢价方法（akshare 主、efinance 兜底，fail-open） |
| 分类映射 | `src/data/etf_sector_mapping.py`（或 JSON 配置） | ETF → 板块 / 指数桶；akshare 分类为主、手工补映射 |
| 计算 / 编排 | `src/services/etf_capital_flow_service.py` | 分类 → 按规模排序 → 取前 10 → 聚合（求和 / 加权）→ 产出 A/B/C 三视角 |
| 持久化 | `src/repositories/etf_capital_flow_repo.py` | 存 / 取每日快照 |
| API | `api/v1/endpoints/etf_capital_flow.py` + `api/v1/schemas/etf_capital_flow.py` | Web 读库接口 |
| 报告注入 | market-review 组装处（实现阶段精确定位）+ 报告渲染 | 喂"资金方向（ETF）"段 |
| 前端 | `apps/dsa-web/src/pages/EtfCapitalFlowPage.tsx` + `api/etfCapitalFlow.ts` + `types` + 导航 / i18n | Web 看板 |
| 定时 | `.github/workflows/00-daily-analysis.yml`（market-review 步骤） | 每日收盘后跑 |

**报告注入落点**：现有大盘复盘报告已有"## 资金方向"段（含北向资金、轮动活跃，见 `tests/fixtures/notification_reports/market_review_report.md`），ETF 资金面接进去即可，不新建报告类型。

## 5. 数据模型

### 单 ETF 快照（来自批量接口）
`code, name, 桶(板块/指数), 总规模, close, 涨幅%, 成交额, 净流入额, 份额变动(额/率), 折溢价%, 桶内规模排名`

> **字段 caveat**：ETF 的"主力净流入（大单）"不一定全市场可得；ETF 真正的机构信号是**份额变动（净申购 / 赎回）+ 折溢价**。落地第一步必须验证 akshare `fund_etf_spot_em` / `fund_etf_fund_daily_em` 实际返回哪些列，缺的字段降级标注 `missing`，**不编造**。

### 桶聚合（每板块 / 每指数一行）
`桶名, 类型(sector/index), 成员数, 总规模, 净流入(求和), 加权涨幅, 加权份额变动率, 加权折溢价, 净流入排名, 连续净流入天数`

### 每日结果
`日期, C 全市场排行(净流入 Top / 流出 Top), A 板块桶[], B 指数桶[], 明细 Top10[], status, source_chain, warnings`

## 6. 每日任务数据流

挂进现有 market-review 流程（复用 `--market-review` 链路，不新建调度）：
1. 批量拉全市场 ETF（akshare 主，efinance 兜底，fail-open）
2. 分类打桶 → 每桶按规模排序 + 流动性下限 → 取前 10
3. 聚合（绝对量求和 / 比率规模加权）
4. 算 C 全市场排行 + A/B 桶排行 + 连续天数
5. 落库（方案 A：当日一份 JSON 快照）
6. 注入报告

## 7. 报告注入（交付面 ①）

新增结构化 block 进 market-review 的 `enhanced_context`，LLM 据此写摘要，并附一张紧凑表。示例：

```markdown
## 资金方向（ETF）
- 净流入板块 Top3：券商(+12.3亿)、半导体(+8.1亿)、有色(+6.4亿)
- 净流出板块 Top3：医药(-5.2亿)、地产(-4.1亿)
- 宽基动向：沪深300 份额+1.8亿（连续3日净申购，疑似国家队），科创50 折价-0.3%
- 结论：资金切向大金融+科技，避险情绪回落
```

**分区**：
- **顶部 KPI 条**：全市场净流入总额、流入 / 流出板块数、领涨 / 领跌板块、数据源 + 时间 + 状态徽标（ok / partial / failed）
- **C 全市场**：双向条形图（净流入 / 流出 Top10 ETF）
- **A 板块轮动**：板块 × 交易日热力图（红 = 净流入、绿 = 净流出、深浅 = 强度）——轮动核心可视化；下接板块排行表（加权各指标 + 连续天数 + 可展开前 10 明细）
- **B 宽基动向**：每只宽基一行 / 卡，份额净申购 + 连续天数用 ★ 醒目标记（国家队信号）
- **明细区**：点击下钻桶内前 10 成员 + 单 ETF 趋势小图

**交互**：日期切换回看、板块行展开 / 下钻、视角切换聚焦 A/B/C；数据状态非 ok 时顶部徽标变黄并显示缺口说明。

## 9. 容错与降级（对齐 AGENTS.md 护栏）

- 批量拉取 fail-open：akshare 挂了走 efinance，全挂则该日 block 标 `partial / failed`，**不拖垮 market-review 主流程**
- 分类缺口：未分类 ETF 进"其他"桶并 warning，不丢数据
- 字段缺失：缺折溢价 / 份额变动 → 该指标标 `missing`，其余照常
- 单一来源失败不阻断（沿用 `get_capital_flow_context` 的 `source_chain / status` 模式）

## 10. 测试策略

- **聚合纯函数**：规模加权平均正确性（专门防"简单平均"回归）、绝对量求和、连续天数计算
- **选样**：按规模取前 10 + 流动性下限的正确性
- **分类映射**：覆盖度与边界（跨主题 / 未分类）
- **repo**：存 / 取最新、按日范围
- **API 契约**：仿 `tests/test_backfill_api.py`
- **fail-open**：数据源失败仍返回 partial、不抛穿
- **前端**：看板渲染 + 状态徽标 + 下钻交互（vitest + RTL，仿现有组件测试）

## 11. 待验证 / 风险

- **批量接口字段**：akshare `fund_etf_spot_em` / `fund_etf_fund_daily_em` 实际返回列需实测（净流入 / 份额变动 / 折溢价是否齐全）；缺字段则降级
- **板块分类覆盖度**：akshare ETF 分类对新主题 / 跨主题 ETF 可能不全，需手工补映射并维护
- **代码时效**：宽基 / 行业主力 ETF 代码会随清盘 / 合并 / 换主力变化；本期不手工列单，靠"按规模前 10"动态算，规避此风险
- **运行时**：批量接口为单 / 少次请求，运行成本与现有 market-review 相当；逐只深拉不在本期方案
- **国家队判定**：份额连续净申购仅为"疑似"信号，报告措辞不写死结论
